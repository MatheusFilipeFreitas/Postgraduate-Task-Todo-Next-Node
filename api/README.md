# Task Todo API

REST API for user authentication and task management, built with **Express** and **TypeScript**. Data is persisted in **PostgreSQL**.

Designed for learning and local development, with production-oriented practices: JWT auth, password hashing, input validation, rate limiting, security headers, and database migrations via **node-pg-migrate**.

## Features

- User registration and login with JWT (httpOnly cookie or Bearer token)
- CRUD operations for tasks (scoped per user)
- UUID-based identifiers
- PostgreSQL persistence with connection pooling
- Docker Compose for local database
- TypeScript migrations managed by **node-pg-migrate**
- Seed data for quick testing
- Layered architecture (routes → services → repositories)
- Security middleware (Helmet, CORS, rate limiting)
- Postman collection included
- Works with **npm**, **pnpm**, and **yarn**

## Requirements

- Node.js >= 18
- Docker & Docker Compose

## Getting started

### 1. Environment variables

```bash
cp .env.example .env
```

| Variable | Description | Default |
|----------|-------------|---------|
| `PORT` | API server port | `3001` |
| `NODE_ENV` | Environment | `development` |
| `JWT_SECRET` | Secret key (min. 32 chars) | — |
| `CORS_ORIGINS` | Allowed origins (comma-separated) | `http://localhost:3000` |
| `DB_HOST` | PostgreSQL host | `localhost` |
| `DB_PORT` | PostgreSQL port | `5432` |
| `DB_NAME` | Database name | `task_todo` |
| `DB_USER` | Database user | `task_todo` |
| `DB_PASSWORD` | Database password | `task_todo` |
| `DATABASE_URL` | Connection string (used by migrations) | `postgresql://task_todo:task_todo@localhost:5432/task_todo` |

Optional Docker overrides in `docker/.env.example` (`POSTGRES_DB`, `POSTGRES_USER`, etc.).

### 2. Install dependencies

**npm**
```bash
npm install
```

**pnpm**
```bash
pnpm install
```

**yarn**
```bash
yarn install
```

> **pnpm note:** If `pnpm dev` fails on `tsx`, run `pnpm approve-builds` once and select `esbuild`.

### 3. Start PostgreSQL

```bash
npm run docker:up
# or: pnpm docker:up / yarn docker:up
```

This command:

1. Starts the PostgreSQL container
2. Waits until the database is healthy (`--wait`)
3. Runs `db:setup` on your machine (migrate + seed)

**Reset database** (wipes volume, then re-runs setup):

```bash
npm run docker:reset && npm run docker:up
```

### 4. Run the API

**Development** (hot reload)

```bash
npm run dev
```

**Production**

```bash
npm run build
npm run start
```

> The `dist/` folder is generated by `build` — do not commit it. It is recreated automatically.

## Docker

The Docker setup runs **only PostgreSQL**. Migrations and seeds run from the **host** (your machine), not inside the Postgres container.

```
docker/
├── docker-compose.yml    # PostgreSQL service
└── .env.example          # Optional Docker env overrides
```

| Script | Description |
|--------|-------------|
| `docker:up` | Start PostgreSQL → wait for health → migrate → seed |
| `docker:down` | Stop PostgreSQL container |
| `docker:logs` | Follow PostgreSQL logs |
| `docker:reset` | Remove database volume (full reset) |

### When do migrations run?

| Trigger | Runs migrations? | Notes |
|---------|------------------|-------|
| `npm run docker:up` | Yes | Via `db:setup` on host after DB is healthy |
| `npm run dev` / `npm run start` | Yes | API applies pending migrations on startup |
| `npm run db:migrate` | Yes | Manual |
| `docker compose up` alone | No | Only starts Postgres — run `db:setup` yourself |

Migrations are **not** executed inside the Postgres container on creation. They run via **node-pg-migrate** from the API project.

## Database migrations

Migrations live in `migrations/` as TypeScript files and are managed by **[node-pg-migrate](https://github.com/salsita/node-pg-migrate)**.

```
migrations/
├── 1720000000000_enable-extensions.ts
├── 1720000001000_create-users.ts
└── 1720000002000_create-tasks.ts
```

Applied migrations are tracked in the `pgmigrations` table.

| Script | Description |
|--------|-------------|
| `db:migrate` | Apply pending migrations |
| `db:migrate:down` | Rollback last migration |
| `db:migrate:create <name>` | Generate a new migration file |
| `db:seed` | Insert sample data |
| `db:setup` | Wait for DB → migrate → seed |

### Create a new migration

```bash
npm run db:migrate:create add-user-avatar
# Edit migrations/<timestamp>_add-user-avatar.ts
npm run db:migrate
```

Example migration file:

```typescript
import type { MigrationBuilder } from "node-pg-migrate";

export async function up(pgm: MigrationBuilder): Promise<void> {
  pgm.addColumn("users", { avatar: { type: "varchar(500)", notNull: false } });
}

export async function down(pgm: MigrationBuilder): Promise<void> {
  pgm.dropColumn("users", "avatar");
}
```

## API endpoints

### Auth

| Method | Route | Auth | Body | Response |
|--------|-------|------|------|----------|
| `POST` | `/auth/register` | No | `username`, `email`, `password` | `{ id, username, email }` — **201** |
| `POST` | `/auth/login` | No | `email`, `password` | `{ id, username, email, token }` + `auth-jwt` httpOnly cookie — **200** |
| `POST` | `/auth/logout` | No | — | `{ ok: true }` — clears cookie — **200** |
| `GET` | `/auth/session` | Bearer token or cookie | — | `{ authenticated: true }` — **200** |
| `GET` | `/auth/user` | Bearer token or cookie | — | `{ id, username, email }` — **200** |

### Tasks

Protected routes accept `Authorization: Bearer <token>` or the `auth-jwt` httpOnly cookie set on login.

| Method | Route | Body | Response |
|--------|-------|------|----------|
| `GET` | `/tasks` | — | `[{ id, userId, title, status }]` — **200** |
| `GET` | `/tasks/:taskId` | — | `{ id, userId, title, status }` — **200** |
| `POST` | `/tasks` | `title` | `{ id, userId, title, status }` — **201** |
| `PATCH` | `/tasks/:taskId` | `status` | `{ id, userId, title, status }` — **200** |
| `DELETE` | `/tasks/:taskId` | — | No content — **204** |

### Health

| Method | Route | Response |
|--------|-------|----------|
| `GET` | `/health` | `{ status: "ok", database: "connected" }` — **200** |

### Error codes

| Status | When |
|--------|------|
| **400** | Invalid input, missing fields, bad token format |
| **401** | Missing/invalid token, wrong login credentials |
| **404** | Route or task not found |
| **500** | Unexpected server error |

### Task status values

`pending` · `in_progress` · `completed`

### Authentication

Protected routes accept either:

| Method | Header / cookie | Set by |
|--------|-----------------|--------|
| Bearer token | `Authorization: Bearer <token>` | `POST /auth/login` JSON response |
| httpOnly cookie | `auth-jwt` | `POST /auth/login` `Set-Cookie` header |

Cookie options:

| Option | Development | Production |
|--------|-------------|------------|
| `httpOnly` | `true` | `true` |
| `secure` | `false` | `true` |
| `sameSite` | `lax` | `none` |
| `maxAge` | 7 days | 7 days |

`POST /auth/logout` clears the cookie. CORS is configured with `credentials: true` so browsers can send cookies to allowed origins.

## Usage example

```bash
# Login with seed user (saves httpOnly cookie to cookies.txt)
curl -c cookies.txt -X POST http://localhost:3001/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"john@example.com","password":"secret123"}'

# Get current user with cookie
curl -b cookies.txt http://localhost:3001/auth/user

# Or use Bearer token from login response
curl http://localhost:3001/auth/user \
  -H "Authorization: Bearer <your-token>"

# List tasks with cookie
curl -b cookies.txt http://localhost:3001/tasks

# Logout (clears cookie)
curl -b cookies.txt -c cookies.txt -X POST http://localhost:3001/auth/logout
```

## Postman

Import from `postman/`:

1. `Task-Todo-API.postman_collection.json`
2. `Task-Todo-API.postman_environment.json`

### Quick flow

1. Run **Auth → Login** — saves `{{token}}` and stores the `auth-jwt` cookie in Postman's cookie jar
2. Test Bearer auth: **Auth → Session (Bearer)** or **Tasks → List Tasks (Bearer)**
3. Test cookie auth: **Auth → Session (Cookie)** or **Tasks → List Tasks (Cookie)** (no Bearer header)
4. Run **Auth → Logout** — clears the cookie and `{{token}}`

The collection includes test scripts that validate login response shape, cookie presence, session checks, and logout cleanup.

## Security

- Passwords hashed with **bcrypt** (never returned in responses)
- **JWT** authentication with configurable secret
- **httpOnly cookies** for browser sessions (`auth-jwt` on login, cleared on logout)
- **Helmet** security headers
- **CORS** restricted to configured origins (`credentials: true` for cookie support)
- **Rate limiting** (global + stricter on auth routes)
- Input validation (email, password length, task status enum)
- JSON body size limited to 10kb
